## 1. Architecture summary

The chatbot is an **Amazon Bedrock AgentCore-managed Harness** that:

- classifies each customer message into exactly one of three deterministic
  categories: `BUG_REPORT` -> `create_bug_report` Lambda, `FAQ` -> embedded
  FAQ answer, `OTHER` -> `+1-800-555-0199` phone-line hand-off,
- exposes the bug-report Lambda through a **Bedrock AgentCore Gateway**
  (MCP protocol, `authorizerType=AWS_IAM`),
- persists created tickets in a **DynamoDB** table keyed by `ticketId`,
- uses **Amazon Nova Pro** for both the chat model and the LLM-as-a-judge
  model, and
- is evaluated end-to-end by **Amazon Bedrock Evaluations**
  (LLM-as-a-judge, BYOI).

The implementation drops the Bedrock-managed memory that the harness
would otherwise auto-create; the chatbot is stateless at the user level
(`runtimeSessionId` carries the conversation, and per-turn "open a new
session" maps to a fresh `conversationId` in the eval runner).

## 4. Rubric evidence

### 4.1 Classification and routing
- Deliverable: `system_prompt.txt` - silently classifies customer messages into
  `BUG_REPORT`, `FAQ`, or `OTHER` and dispatches routing accordingly.
- Evidence: 13-test suite (`harness_tests.json`) probes each branch;
  the resulting JSONL is the `Builtin.Correctness` input.

### 4.2 Bug-report path
- Tool: `create_bug_report` Lambda. Writes `ticketId`, `description`,
  `stepsToReproduce`, `environment`, `status="OPEN"`, `createdAt` to the
  `bug-report-tool-stack-bug-reports` DynamoDB table.
- Collection: `system_prompt.txt` Category A tells the harness to ask one
  focused question at a time for any missing of the three fields.
- Evidence: `chat.py --say "<bug report>"` produces a `[tool call]
  create_bug_report(...)` line and the corresponding DynamoDB item
  (`aws dynamodb scan --table-name bug-report-tool-stack-bug-reports`).

### 4.3 FAQ + Other-request paths
- FAQ: `online_shop_faq.md` is embedded in `system_prompt.txt` between
  `--- BEGIN ONLINE SHOP FAQ ---` and `--- END ONLINE SHOP FAQ ---`.
  The system prompt forbids references to anything outside that block.
- Other: `system_prompt.txt` Category C tells the harness to give the
  customer the support phone number `+1-800-555-0199`.
- Edge cases: short messages, prompt-injection attempts, account-deletion
  requests are all explicitly handled to keep the OTHER branch from
  being routed as FAQ.

### 4.4 Testing and evaluation
- Test suite: `harness_tests.json` with one entry per rubric branch plus
  extra edge cases (prompt-injection, vague greeting, account deletion,
  late package, payment methods, return policy).
- Dataset generation: `generate_eval_dataset.py --tests harness_tests.json`
  emits one JSONL line per test in the BYOI format
  `{prompt, referenceResponse, modelResponses:[{response, modelIdentifier}]}`.
- Bedrock Evaluations job: the JSONL is uploaded to the
  `bug-report-testing-stack` S3 bucket and a `Builtin.Correctness` job is
  submitted against `amazon.nova-pro-v1:0` as the LLM-as-a-judge.
- Target: `Builtin.Correctness` close to 1.0.

## 5. How to execute - one-shot

```powershell
cd project\starter

# 1. Paste the AWS STS triplet into the four $env lines at the top of
#    run_all_inprocess.py before launching - see its docstring for the
#    exact variable names.
#
# 2. Run:
python run_all_inprocess.py
```

`run_all_inprocess.py` does this in order:

1. probes your STS triple via `aws sts get-caller-identity`,
2. re-attaches the Lambda target to the AgentCore Gateway,
3. creates / updates the Harness with memory disabled,
4. pushes a broad IAM permission set onto the harness role
   (`InvokeBedrockAny` + `BedrockLogs` + `AgentCoreAll`) so the runtime
   can call `InvokeModelWithResponseStream` on the inference profile and
   read/write its managed resources,
5. fires one chat message per branch (bug, FAQ, OTHER, prompt-injection),
6. deploys `bug-report-testing-stack` if missing,
7. runs `generate_eval_dataset.py` against `harness_tests.json`,
8. uploads `output_eval_dataset.jsonl` to the eval bucket,
9. submits a `Builtin.Correctness` Bedrock Evaluations job,
10. tears down the AgentCore harness -> target -> gateway, empties the
    bucket, and deletes both CloudFormation stacks.

Step 10 leaves no AWS resources running.

## 6. Troubleshooting seen during build

| Symptom | Root cause | Fix |
|---|---|---|
| `Gateway service is not authorized to AssumeRole` | The default CFN trust for gateway/harness roles was `bedrock.amazonaws.com`. | Trust rewritten to `bedrock-agentcore.amazonaws.com`. |
| 403 on the gateway MCP URL during `InvokeHarness` | Harness execution role lacked `bedrock-agentcore:InvokeGateway`. | Inline policy adds it. |
| `AccessDenied: bedrock-agentcore:ListEvents` | Harness auto-attaches a managed memory even when `memory` wasn't set; runtime needs `ListEvents`. | `update_harness(memory={"optionalValue":{"disabled":{}}})` after creation. |
| `AccessDenied: InvokeModelWithResponseStream` on `arn:aws:bedrock:us-east-1:<acct>:inference-profile/...` | Default CFN listed only the foundation-model ARN. | Inline policy adds the inference-profile ARN. |
| `ThrottlingException: Too many tokens per day` (Nova Pro) | Account's daily Nova quota already burnt. | Switch accounts or wait for the daily reset. |
| STS session expires mid-pipeline | STS lifetimes in this account are short. | Use `run_all_inprocess.py`; it does the whole pipeline in one Python process. |
